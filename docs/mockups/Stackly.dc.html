Stackly is still running
Closing the window doesn’t stop stacklyd or your instances. Use the menu bar icon to reopen it.
Welcome to Stackly
Run local databases, queues and proxies side by side, each with its own data, port and secret.
Isolated instances
Several versions of the same server, never touching each other’s data.
Verified runtimes
Downloaded, checked against a pinned digest, then committed.
Environments as files
A stackly.yaml per project. Plan, then bring everything up in order.
Keep services running in the background
stacklyd supervises your instances when the window is closed. macOS asks you to allow it in Login Items.
Allowed in Login Items
stacklyd starts when you log in.
Waiting for approval
Without it, the daemon runs only while the app is open.
Where your data lives
Everything stays in your user Library. Instance data is kept by stable ID, so renaming never moves files.
Data~/Library/Application Support/Stackly
Cache~/Library/Caches/Stackly
Logs~/Library/Logs/Stackly
SecretsLogin Keychain
Choose catalog sources
Providers describe how to install and run each server. Only trusted sources appear in the catalog.
official
Maintained by the Stackly project. Signed manifests, pinned artifacts.
community
Reviewed in public, not by maintainers. Trust each provider explicitly.
Command line tool
The app and the CLI talk to the same daemon, so changes in one show up in the other.

$ stackly env up ~/Code/erp
